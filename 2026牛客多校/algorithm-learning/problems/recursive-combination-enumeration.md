# 递归组合型枚举：从 n 个数中选 m 个

## 题意抽象

根据代码推断，程序需要从集合 `{1, 2, ..., n}` 中恰好选出 `m` 个数，并输出所有组合。

## 数据范围与复杂度要求

代码未提供题目数据范围。组合数量为 `C(n,m)`，最坏情况下递归树规模为 `O(2^n)`；如果输出每组组合，输出本身还需要 `O(m * C(n,m))` 时间。递归深度和当前方案空间均为 `O(n)`。

## 涉及知识点

- 递归指数型枚举；
- 组合型枚举：每个元素进行“选/不选”决策；
- 回溯与恢复现场；
- 可行性剪枝。

## 思路推导

`dfs(cur)` 表示正在决定数字 `cur` 是否加入当前组合，`chosen` 保存已经选择的数字。

每层有两条分支：

1. 选择 `cur`，递归处理 `cur + 1`；
2. 弹出 `cur` 恢复现场，再递归处理“不选择 `cur`”的分支。

当 `cur > n` 时，`1..n` 已经全部完成决策。只有 `chosen.size() == m` 时才输出。

## 核心不变量或正确性

- 进入 `dfs(cur)` 时，`chosen` 中保存的正是此前已经选择的数字；
- `chosen.push_back(cur)` 和递归返回后的 `pop_back()` 保证两条分支互不污染；
- 若 `chosen.size() > m`，当前分支不可能合法；
- 若 `chosen.size() + (n-cur+1) < m`，即使剩余数字全部选择也无法达到 `m`，当前分支不可能合法；
- 每个数字只有选和不选两种决策，因此每个大小为 `m` 的组合恰好被枚举一次。

## 我的实现

你的实现采用了正确的“选/不选 + 回溯 + 数量剪枝”结构。`cur > n` 作为终止条件与从 `dfs(1)` 开始的递归起点匹配。

## 时间与空间复杂度

- 递归搜索最坏为 `O(2^n)`；
- 输出成本为 `O(m * C(n,m))`；
- 额外空间为 `O(n)`。

## 错误、反例与修复

最终代码已通过评测。调试过程中实际出现的错误是混淆了“数量可行性剪枝”和“递归终止条件”。

### 1. 将数量剪枝误写成递归终止条件

之前曾将本应写成：

```cpp
if (a.size() > m || a.size() + (n - cur + 1) < m) {
    return;
}
```

的代码误写为：

```cpp
if (cur > n) {
    return;
}
```

两者职责不同：`cur > n` 只能说明 `1..n` 已经全部决策完，是递归的终止条件；数量剪枝则要根据“当前已经选了多少”和“剩余还能选多少”判断当前分支是否可行。修复时应同时保留数量剪枝和终止条件。

其他需要注意的边界：

- `m > n` 时，根节点的“剩余数量不足”剪枝会直接结束，不输出任何组合；
- `m == 0` 时，会输出一个空组合，对应一行空行；是否符合题目格式要看原题要求；
- 当前输出每组组合后有一个尾随空格，通常不影响评测；若要求严格格式，可改为按下标控制空格；
- 以后若把终止条件改为 `cur == n + 1`，也必须保留终止后的 `return`。

## 可迁移经验

遇到“从若干元素中选出固定数量”的题目，可以先写成每个元素“选/不选”的指数型递归，再用两个数量判断剪枝：已经选了多少，还剩多少可选。判断 `cur` 含义时，要明确它是“当前正在处理的元素”还是“下一个待处理元素”，再确定终止条件。
