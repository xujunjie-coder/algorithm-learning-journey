# Palindrome

## 来源与章节

- 题号：NC50987
- 链接：[牛客题目页面](https://ac.nowcoder.com/acm/problem/50987)
- 相关学习章节：0x04 基本算法-二分
- 主要知识点：字符串哈希、二分答案、奇偶回文分类
- 评测状态：用户报告已 AC

题目要求对长度最多 `1000000` 的字符串求最长回文子串长度，输入以 `END` 结束；C/C++ 时间限制为 1 秒、空间限制为 32 MB。

## 题意抽象

在一个字符串中寻找长度最大的连续区间，使该区间正读和反读完全相同。

## 涉及知识点

- 核心算法：滚动哈希 + 二分答案；
- 辅助技巧：正向字符串与反串的区间映射；
- 二分变体：奇数回文半径和偶数回文半长度分别二分；
- 实现细节：1-based 字符串、`unsigned long long` 自然溢出哈希。

## 思路推导

给原串加一个前导空格，采用 1-based 下标。构造原串哈希 `f`、反串哈希 `rf` 和幂数组 `p`。

对于原串区间 `[l,r]`，反串中的对应区间为：

```text
[n-r+1, n-l+1]
```

两段哈希相等即可判断该区间是回文。

不能直接二分“是否存在长度恰好为 `x` 的回文”，因为奇偶长度交错后不具备单调性。因此分别二分奇数回文半径和偶数回文半长度。

## 核心不变量或正确性

若某个中心存在半径 `k` 的奇数回文，则同中心的所有更小半径也都是回文；偶数回文同理。因此奇数和偶数判定各自满足二分单调性。

## 错误、反例与修复

1. 最初将

   ```cpp
   f[i] = f[i-1] + value;
   ```

   得到的前缀和与多项式哈希查询公式混用。修复为：

   ```cpp
   f[i] = f[i-1] * BASE + value;
   ```

2. 反串查询最初使用了 `[l,r]`，修复为 `[n-r+1,n-l+1]`。

3. 右端点循环不能写成 `r < n`，否则无法检查以最后一个字符结尾的区间。

4. 最大可行值二分需要上取中点，否则在 `r=l+1` 且 `check(mid)` 为真时会死循环。

5. 单次二分不能直接处理所有长度，必须拆分奇数和偶数回文。

6. 本题对二分答案的单调性理解不够充分，把“是否存在长度恰好为 `x` 的回文子串”当成了可以直接用于全局二分的判定条件。长度 `12` 不是回文，并不代表长度 `13` 也不是回文；不同奇偶长度之间不存在这样的单调关系。

   修复方式：不直接二分回文长度，而是将回文按奇偶分类，分别二分回文半径。对固定中心而言，如果半径 `k` 的回文存在，那么更小半径的回文也一定存在，因此判定才具有单调性：

   - 奇数回文：二分半径 `k`，长度为 `2k+1`；
   - 偶数回文：二分半长度 `k`，长度为 `2k`。

## 复杂度

滚动哈希预处理为 `O(n)`；每次判定扫描所有中心，为 `O(n)`；奇偶各进行一次二分，总复杂度为 `O(n log n)`，空间复杂度为 `O(n)`。

该实现使用 64 位自然溢出哈希，存在理论碰撞可能；若需要确定性线性复杂度，应使用 Manacher，复杂度为 `O(n)`。

## 本题错误总结

我对二分答案的单调性理解不够熟练，忽略了在设计 `check` 函数之前必须先确认可行性是否具有单调性。最初试图在所有回文长度上直接寻找全局最长长度，但“存在长度恰好为 `x` 的回文子串”并不单调：长度 `12` 不是回文，不代表长度 `13` 不是回文。

对应修改是把问题转化为回文半径问题：奇数回文和偶数回文分别处理，并分别二分半径。固定中心后，半径越小，回文性质仍然成立，才能使用二分答案。
