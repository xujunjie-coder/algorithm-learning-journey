## 题意抽象

将所有正整数长度小段恰好使用一次，分成若干组，每组总长相同，求最小组长 L。总长 S 不变，因此 L >= max(a)，且 S % L == 0；满足这两个条件仍须检验能否分组。

## 数据范围与复杂度要求

截图约束：最多 64 段，每段长度为 1~50，多组输入，以 n=0 结束。故 S<=3200，int 足够，N=70 可容纳。

64 个对象不适合直接使用 2^n 的集合 DP。回溯最坏仍是指数搜索，必须识别等价分支，不能因代码简短就认为搜索量小。

## 涉及知识点

- 核心算法：枚举候选答案，将最小化问题转为等长分组的 DFS 可行性检验。
- 辅助技巧：降序搜索、同组下标递增、同层等长去重、空组首段固定、恰好补满失败剪枝。
- 实现细节：局部变量初始化、状态值与标记一致、回溯恢复、循环内外 return 的作用范围。
- 本题转化：组长为 S 的约数，所需组数 tar=S/L；保留于本复盘，不为约数枚举单独建卡。

## 思路推导

1. 先固定 L，最朴素地每次枚举所有未用小段，放入当前原木；不能超过 L，达到 L 就开始下一根。
2. cur_len 表示当前原木已拼长度，fineshed 表示已完成根数，used 表示资源使用情况。初始 dfs(0,0) 表示未选任何段。
3. 为避免同一组小段的排列重复，再增加 start：同一根内部选 i 后从 i+1 开始，换根则从 0 开始。最终入口 dfs(0,0,0)。
4. 同一次调用中，某个长度的后续方案失败后，令 last=a[i]，跳过后续等长段。last 每层独立，初始化为 -1。
5. 空原木固定剩余第一段：它总要属于某根原木，可以先拼包含它的那根。其所有后续方案失败后，无须更换开头；只返回当前调用，上层仍能调整前面的分组。
6. 恰好补满失败：若当前已拼部分为 P、缺口为 x，存在单段 x。任何使用一组总长 x 的小段 B 补满的成功方案，都能将 B 与另一根中的单段 x 交换，得到 P+x 的成功方案。因此单段补满后的全部后续搜索失败，则其他补法也不可能成功。这证明的是可行性，不是单段在某个目标上“更优”。

## 核心不变量或正确性

- 每次调用中 used 为真的段，其长度和为 fineshed*tar_len+cur_len，且每段只使用一次。
- 新组从 start=0 开始；同组下标递增不漏组合，因为任意组合都可按下标排序。
- 正长度保证 fineshed==tar 且 cur_len==0 时，已用长度为 S，不可能剩下未用段。当前实现只在拼满时增加 fineshed，并把 cur_len 归零。
- 局部传值的 cur_len 不因子调用而改变；used 是共享数组，需要恢复。递归调用返回且 found 为假，代表这一选择的整个后续搜索已经失败，不只是某一个直接子选择失败。
- 两个失败剪枝在递归返回、恢复 used、排除成功之后执行。提前放在递归前会跳过尚未检验的方案；放在循环外则已试完所有兄弟分支，失去剪枝作用。
- 按 L 递增枚举，首个成功候选即最小答案；本题可行性不是普通数值区间上的单调性质，不直接套二分答案。

## 我的实现

最终提交文本原样保存在 [用户最终代码](../reviews/sticks-min-original-length-submitted.cpp)，保留 fineshed 等原命名。证据为用户报告评测通过，未另外声称已执行本地测试。

循环末尾为：

```cpp
used[i] = 0;
if(found) return;
last = a[i];
if(cur_len == 0) return;
if(cur_len + a[i] == tar_len) return;
```

当前代码不需要在候选间额外重置 found/used：失败时 found 始终为假且所有标记恢复；成功时立即输出 break；下一组数据 init 重置。未把“没有逐候选重置”记录为错误。

## 时间与空间复杂度

每个合法候选的搜索可保守用 O(n*n!) 上界描述：深度至多 n，每层扫描至多 n 个对象，选段顺序不超过所有部分排列。候选数至多 S，故粗略上界 O(S*n*n!)；实际由约数过滤和剪枝显著降低，但不承诺多项式时间。排序 O(n log n)，额外数组与递归栈 O(n)。

用户报告去掉“恰好补满失败”剪枝会超时；未提供对应输入与计时，不虚构性能数字。该剪枝能省掉用不同组合补同一缺口以及它们各自后续的整棵子树，last 和空组剪枝不能替代它。仅用“原木顺序的阶乘”解释这一剪枝不准确，那主要对应空组首段固定。

## 错误、反例与修复

| 实际代码或理解卡点 | 问题与最小检查例 | 修复及反映的不熟练处 |
|---|---|---|
| 枚举 i 时写 sum % ans | ans 实际保存最大段；[3,2,1] 总长 6，候选 4 不应进入检验，但 sum%ans 为 0 | 改 sum%i；外层枚举变量与固定下界的角色尚易混淆 |
| used[0]=1 后 dfs(a[1],1) | 标记第 0 段，却用第 1 段作为当前长度；“已完成一根”后新根也不应凭空带长度 | 统一从 dfs(0,0) 开始；状态、已完成数量与标记未保持一致 |
| dfs(a[0],0) 却没标记 used[0] | [2,1,1] 检验 L=2：长度已含第 0 段，它仍被视为可再次使用，入口不变量已经破坏 | 从空局面开始，让 DFS 自己选第一段 |
| 初版找到答案后没有输出和 break | [1] 应输出 1，初版无输出；还会继续枚举 | found 后输出候选并 break；搜索与主流程衔接需检查 |
| int last 未初始化 | 第一次读取无确定值，不能当作“尚未尝试” | int last=-1；局部变量初始化仍需习惯化 |
| last=used[i] | used[i] 刚恢复为 0，导致 last 总记 0；例如 [2,2,1,1] 的同层两个 2 无法去重 | last=a[i]；要记清变量保存的是长度而非布尔状态 |
| 以为循环后的 return 已等同空组剪枝 | 循环外要等全部兄弟选择完成；循环内能跳过剩余兄弟 | 需手绘一棵递归树，区分函数调用、循环分支和整棵子树 |
| 以为空组剪枝只适用于第一根 | 每次拼满都调用 dfs(0,0,fineshed+1)，新的一根 cur_len 同样为 0 | 跟踪参数值，区分“程序首次调用”和“每根原木的开始” |
| 不清楚失败剪枝为何放递归之后 | 前置会尚未检验就返回，循环外又无法提前省分支 | 用“选择→子树搜索→恢复→成功传递→失败剪枝”解释代码位置 |
| 将补满剪枝理解成“单段比多段更好” | 题目不优化段数；需要证明替代方案不会产生新的可行性 | 用等长交换给出证明，再写失败后的 return |
| 不理解去掉一行为何超时 | 只看到当前循环的工作量，尚未把一次递归理解为可能很大的子树 | 观察失败候选：不同补法各自重搜后续分组，不凭代码行数估时 |
