# 班级合照：记忆化搜索计数复盘

## 来源与章节

## 题意抽象

在左对齐、从后向前人数不增的队形内安排不同身高的学生，使每行和每列均从高到矮，计算合法排列数。

## 数据范围与复杂度要求

最多 5 排、总人数至多 30。第 i 排容量最多 floor(30/i)，因此五维数组可开 [31][16][11][8][7]，包含已放人数 0。答案保证适合无符号 32 位整数，使用 long long 累加。

## 涉及知识点

- 核心：记忆化搜索计数。
- 辅助：根据未来行为合并状态；利用人数序约束估算每维上界。
- 实现：闭区间初始化、未计算哨兵、多组清零、按值传参与计数类型。
- 本题变换：按身高递减放人，用每排已放人数替代具体人员布局。

## 思路推导

从 (2,1) 队形检查最高者的位置，确定上方和左方必须已填。逐个安排从高到矮的人，遇到多个合法位置就分别搜索。每排已占位置总是连续前缀，因此保存每排人数即可。

不同编号布局可以产生相同人数状态，它们后面的合法位置与后缀数量一致。用户由此提出记忆化搜索。令 dfs(a,b,c,d,e) 表示从当前状态继续的方案数，枚举增加一排的人数，各分支相加，全满时返回 1。

完整对话推导与错误反例保留在[学习记录](../reviews/young-tableaux-learning.md)。

## 核心不变量或正确性

状态中每排均为已填前缀，已放学生均比未来学生高。增加第 i 排的条件是未满且上一排已填到新位置；这保证引入的所有相邻身高约束。完整合法排列对应唯一的按身高递减放置序列，因此分支相加不重不漏。同状态具有相同后缀约束，可以缓存。

## 我的实现

保留[用户报告 AC 的完整代码](../reviews/young-tableaux-photo-submitted.cpp)，没有改写用户风格。最终修正了初始化五层循环的 <=，以及每组读入前清零五排容量。命中缓存后 ans += memo 再统一返回的写法正确。

## 时间与空间复杂度

S=乘积(n_i+1)，时间 O(5S)，缓存理论空间 O(S)，递归栈 O(N)。用户代码固定数组为 305536 个 long long，2444288 字节，约 2.33 MiB；声明 [31]^5 时约 218.42 MiB。未根据未知内存限制宣称必定超限。

## 错误、反例与修复

| 本次表现 | 对应未理解或尚不稳固的点 | 本次澄清与后续复习 |
|---|---|---|
| 最初认为最高者可在第一排任意位置 | 行、列约束需要同时检查 | 最高者在右上时，其左邻要求更高，产生矛盾；后续能识别合法位置 |
| 在已知合法放置规则后，仍不知道如何枚举 | 从局部选择构造完整搜索树 | 用三人队形逐分支尝试；需要独立写一次暴力搜索 |
| 第一次写第二排转移只检查未满 | 条件不能只检查容量，还要检查上方依赖 | 补上 a >= b+1；之后用户独立写出第三排和五排扩展 |
| 询问如何判断放完 | 状态与终点条件的对应关系未熟练 | 每排已放人数均等于容量；用户理解终点返回 1 |
| 用 if(memo) 判断缓存 | 未计算标记与布尔真假混淆 | -1 也是 true，必须比较 != -1；已修正 |
| 对缓存与所有可能的解释较笼统 | 记忆化合并计算，不合并不同前缀的计数贡献 | 两个前缀各接 x 个后缀应贡献 2x，仍需独立解释巩固 |
| 第二排上限回答 29 | 总人数与排长单调性联合推界不熟练 | 第二排 x 人则前两排至少 2x，故至多 15；随后能推出第三排至多 10 |
| 询问数组内存怎么算 | 维度乘积、元素字节数和 MiB 换算未建立 | 元素数乘 sizeof(long long)，再除 1024²；已讲解，待独立计算 |
| 初始化反复写 <，追问为何 <= | 已放人数是 [0,容量]，与数组遍历 [0,长度) 混淆 | 容量 2 要初始化 0、1、2；容量 0 也要初始化 0；最终代码已改正 |
| 没有每组清零容量 | 全局数组只在程序开始清零，多组数据会残留 | 从五排切换到一排会保留尾部容量；最终代码已加入 fill |
| 初版三维 fill 和 int 累加 | 多维数组初始化方式、计数值域需复核 | 改为遍历各维，累加使用 long long |

历史错误版零容量导致初始化跳过的最小反例：输入 1、1、0（各自一行），正确输出 1，原版误命中默认缓存 0。多组重置可检查先输入五排各 1 人，再输入一排 2 人，两组均应输出 1。

## 补充一：从记忆化搜索改写为递推 DP

dp[a][b][c][d][e] 表示到达当前人数状态的前缀方案数。全部清零后空状态设为 1，五层循环正序遍历，每个合法转移把当前值累加到增加一排人数的目标。最终输出容量状态。具体推导与代码见[记忆化搜索计数卡的递推补充](../knowledge/动态规划/记忆化搜索计数.md)。

本次理解缺口：用户把空状态方案数回答为 0，说明混淆人数与方案数；通过“空安排能延伸出第一种安排”澄清。后续用户能给出 += 转移和正序原因，完整代码按用户请求由助手提供，没有据此宣称独立编写。

## 补充二：杨图、标准杨表与勾长公式

左对齐、行长不增的格子形状叫杨图；填入 1...N 各一次且行列严格递增得到标准杨表。最高者编号最小，因此本题恰好是给定形状的标准杨表计数。关于“杨氏矩阵”与这些术语的区别、公式含义和来源，见[杨图与勾长公式卡](../knowledge/组合数学/杨图与勾长公式.md)。

每格勾长 h=右侧格子数+同列下方格子数+1。0-based 格子 (i,j) 的 h 从 n[i]-j 开始，对每个下方且 n[r]>j 的行再加 1。数量为 N! 除以所有 h 的乘积，(3,2,1) 的勾长为 5,3,1 / 3,1 / 1，结果为 16。

30! 超过 long long，不能先计算阶乘。保存各分子因子，用 gcd 与每个勾长逐步约分，再乘剩余分子。&& h>1 是可省略的提前退出优化，分母已消去后再约不会改变结果。

本次理解缺口：右侧格子数最初写成 n[i]-i+j+1，说明行列下标尚混淆；讲解后能正确计算例子。下方格子存在条件 n[r]>j 由用户正确给出。用户询问 && h>1 的意义，已解释与正确性无关、只提前结束。公式完整证明未讲解，不能把会代入记为已掌握证明。
