## 题意抽象

将 n 个不可拆分物品装入若干相同容量 w 的容器，使容器数量最少。每只猫必须且仅须被安排一次；每辆车总载重不超过 w。

## 数据范围与复杂度要求

截图给出 `1 <= n <= 18`，`1 <= c[i] <= w <= 10^8`。

- n 小，适合枚举选择、集合状态和剪枝搜索。
- w 大，不能直接照搬按容量开 `dp[mask][remaining]` 的稠密数组。
- 状压 DP：2^n 个集合，每个尝试 n 只猫，每次 O(1)，所以 O(n*2^n) 时间、O(2^n) 空间。n=18 时约 472 万次内层检查。
- DFS：最坏指数规模，依赖剪枝，不能承诺所有数据固定很快；保守上界 O(n*(n+1)^n)，数组与递归栈 O(n)。降序排序 O(n log n) 不占主要搜索代价。
- 应先用“状态数 × 每状态选择数 × 单次代价”估算，再实现并检查额外开销。DFS 不应直接套 O(n*2^n)。

## 涉及知识点

- 核心算法：固定物品顺序、枚举已有容器或新容器的回溯搜索。
- 辅助技巧：先安排重猫；用已知合法上界 ans 剪掉不可能改善的分支。
- 实现细节：猫编号与车编号分离；修改全局数组后恢复；`fill` 初始化整数数组；参数传值；边界、等号和比较方向。
- 对照算法：用 mask 记录具体猫集合，用二元答案记录车辆数及当前车剩余容量。
- 本题特定约定：DFS 版本枚举所有已有车；状压 DP 版本只扩展最后一辆车，但允许任意选猫顺序，两种状态不能混用。

## 思路推导

### DFS：固定当前猫，选择它坐哪辆车

`dfs(cur,cnt)`：前 `cur-1` 只猫已安排，当前处理 `c[cur]`，已经开车 `1..cnt`。

1. 用 `i` 枚举每一辆已有车；若 `sheng[i] >= c[cur]`，放进去、递归、拿出来。
2. 已有车循环结束后，单独尝试一次新开 `cnt+1` 号车。
3. 所有猫安排完，即 `cur == n+1`，更新答案。
4. 当前车辆数不会随着后续安排减少，因此 `cnt >= ans` 可以剪枝。

### 从用户第一反应修正 DP 状态

用户提出“用了几只猫、用了几辆车、最后一辆车剩多少”。关键修正是“用了几只”不够，必须知道“具体用了哪些”。例如 w=10，已装 `{2,5}` 与 `{3,4}`，数量、车辆数、剩余空间都相同，剩余猫却不同。

用第 j 位标记编号 j 的猫，编号从 0 开始：`1<<0=001`、`1<<1=010`、`1<<2=100`。`mask & (1<<j)` 判断已选；`mask | (1<<j)` 加入猫。

`dp[mask]={cars,remaining}` 保存该集合的优先方案：车辆少优先，车辆相同则剩余空间大优先。`nxt` 起初复制 `dp[mask]`，加入猫后是目标集合的候选答案，再与目标已有答案比较。

“只保存一个二元答案”的理由：相同车辆数下，剩余空间更大的状态能模拟剩余空间较小的状态；若一个状态车辆更少，即使当前车空间较小，也可以主动开一辆空车，在车辆数不超过另一状态的情况下获得至少同样的后续装载能力。故较差状态无需单独保存。

状压转移虽然强制装得下时继续装当前车，仍不漏最优车辆数：把某最优方案的各车猫分组顺次排列，每组总重量 <= w；处理每组时最多新开一辆车（第一次开新车后，该组余下重量 <= w）。所以至少存在一种选猫顺序不超过最优车辆数。它不保证原样复现每种具体分组。

## 核心不变量或正确性

- 本题 DFS 中 `cur` 是猫编号，`i` 是车编号，`cnt` 是已经开的车数量。
- `sheng[i]` 是车 i 的剩余容量；所有未开的车保持 w。
- `sheng[i]-=c[cur]` 前验证装得下；递归返回后 `+=c[cur]`，恢复进入该分支前的数组。
- 新车的减法写法成立，是因为 `sheng[cnt+1]` 进入前为 w，返回后又恢复为 w。
- 固定猫顺序不遗漏分组：任何分组中当前猫要么属于已有车，要么属于此前尚未出现的新车；所有已有车被枚举，新车只需创建下一个编号。
- `cnt > ans` 正确但较弱；`cnt >= ans` 在只求最小值、不统计最优方案数量时也安全。
- 降序只改变搜索先后，不限制搜索方案，不是“每次贪心放进某一辆车”。

## 我的实现

保留[本次提交版本](../reviews/kitten-cable-car-submitted.cpp)，未悄悄替换为助手版本。该版本从 `dfs(1,1)` 开始，一辆空车已计数；n>=1 时仍能得到正确最小值，但可能有额外重复分支。

核心结构及标记：

```cpp
for (int i = 1; i <= cnt; ++i) { // i：车，不是猫
    if (sheng[i] >= c[cur]) {    // cur：当前猫；恰好装满也合法
        sheng[i] -= c[cur];     // 做选择
        dfs(cur + 1, cnt);      // 固定这个选择，处理下一只猫
        sheng[i] += c[cur];     // 恢复共享数组
    }
}
// 新车是独立分支，不是某辆旧车放不下时的 else
sheng[cnt + 1] -= c[cur];
dfs(cur + 1, cnt + 1);          // 不修改本层 cnt
sheng[cnt + 1] += c[cur];
```

[正式 DFS 模板](../templates/dfs-bin-packing.cpp)保留剩余容量和 1-based 写法，只删除未使用的全局 cnt、采用已知上界 ans=n、加强剪枝为 `cnt>=ans`。最新原代码的这些部分并非正确性错误。

### 我的状压 DP 实现与旧错定位

用户在 DFS 归档后补交了完整正确的 DP 版本：[本次 DP 原版](../reviews/kitten-cable-car-dp-submitted.cpp)。保留 i、j、mask、nxt 的命名与比较方向；带对应旧错标记的完整程序见 [DP 模板](../templates/subset-bin-packing.cpp)。两种解法记录在同一道题下，不重复计 encounter，也不自动计作第二次独立解题或一次既有模板使用。

```cpp
int tot = 1 << n;
for (int i = 0; i < tot; ++i)
    dp[i] = {n + 1, 0}; // [旧错 1] 之前漏初始化，默认零车会挡住更新
dp[0] = {1, w};

for (int i = 0; i < tot; ++i) {   // i：旧集合
    for (int j = 0; j < n; ++j) { // j：下一只猫的 0-based 编号
        if (i & (1 << j)) continue;
        auto nxt = dp[i];         // [旧错 4] 复制后要真正修改副本
        if (nxt.second >= c[j]) { // [旧错 2] 曾写 >，漏掉恰好装满
            nxt.second -= c[j];  // [旧错 3] 曾写 w-c[j]，错误重置剩余量
        } else {
            ++nxt.first;
            nxt.second = w - c[j];
        }
        int mask = i | (1 << j);  // 新集合；nxt 现在属于 mask，不再属于 i
        // [旧错 5] 不可直接覆盖：其他路径可能已经给出更好的方案
        // [旧错 6] 相等要写 ==；[旧错 7] 车辆相同，新方案剩余越多越好
        if (dp[mask].first > nxt.first ||
            (dp[mask].first == nxt.first && dp[mask].second < nxt.second)) {
            dp[mask] = nxt;
        }
    }
}
cout << dp[tot - 1].first << '\n'; // 全选集合，不是状态总数 tot
```

注意三个对象：`dp[i]` 是旧集合已保存的答案；`nxt` 起初是副本，在装猫后成为新集合的候选；`dp[mask]` 是新集合先前保存的最好答案。比较发生在同一目标集合的两个方案之间。

例：w=10，两只猫为 6 和 5。先 6 后 5 得到 `{2,5}`，先 5 后 6 得到 `{2,4}`；同属集合 11，应保留 `{2,5}`。若不择优而直接覆盖，答案会依赖枚举顺序。

本题每个子集都可由空集合逐个加入猫得到；加入新猫后 mask 必然更大。因此升序处理时每个集合都已有合法状态，当前程序没有 `if(dp[i].first==n+1) continue;` 仍正确。未使用的全局 ans 和 ll/ull 宏属于冗余声明，不是正确性错误。

两种解法的差别：DFS 固定猫顺序，逐辆尝试车；DP 枚举未选猫，扩展最后一辆车，并合并到达同一集合的较差状态。不要将两份程序的下标和选择语义混用。

## 时间与空间复杂度

DFS 与 DP 分别见数据范围分析。当前 N=20、n<=18，原版最多出现 n+1 辆（含初始空车），1-based 最大下标 19，在数组内。重量与剩余容量均可用 int。不能把 N=20 的声明解读成支持 n=20 的 1-based 数据。

用户 DP 的猫编号是 `0..n-1`。实际声明 `pair<int,int> dp[1<<20]`，固定分配 2^20 对整数，常见每对 8 字节，共约 8 MiB；运行只处理前 2^n 个状态。O(2^n) 描述所需状态量，这份固定上限实现的物理数组是 O(2^N)，不要把两者混为精确内存用量。

## 错误、反例与修复

以下只记录对话中实际出现的错误；当前正确的部分与优化建议分开。

| 先前写法或疑惑 | 原因及可检查例子 | 修复 |
|---|---|---|
| 把“用了几只猫”作为完整集合信息 | w=10，已装 2+5 与 3+4 都是两只、剩 3，但剩余猫不同 | 用 mask 记录具体猫身份 |
| 认为编号 2 对应 010 | 混淆第几只与 0-based 编号 | 编号 2 是第 3 只，`1<<2=100` |
| 不知道两个状态量为何用 pair | 混淆保存两个字段与新增状态维度 | `pair` 可替换 `dp[mask][2]`；不同于 `dp[mask][load]` |
| DP 没有初始化，默认 {0,0} | 第一只猫候选车数为 1，旧值 0 看起来反而更优 | 未达状态 `{n+1,0}`，起点 `{1,w}` |
| 用 `remaining > c[j]` | w=10，剩 4，猫重 4，恰好装满被拒绝 | 用 `>=` |
| 当前车装得下仍写 `w-c[j]` | w=10，旧剩 4，加入 3 后应剩 1，不是 7 | `nxt.second -= c[j]` |
| `nxt` 复制后仍直接覆盖目标 | 副本没有形成候选结果，多条路径更新同一集合会互相覆盖 | 先修改 nxt，再择优保存 |
| 不理解 nxt 为何与 dp[new_mask] 比较 | nxt 已在分支里加入新猫，不再是旧方案 | 比较的是同一新集合的两个方案 |
| 条件中写 `=` 而非 `==` | 会赋值并修改状态，不是在判断相等 | 比较车数用 `==` |
| 剩余容量越小越好 | 同样两辆车，剩 5 优于剩 3 | 车辆相同取剩余量更大的候选；不能直接用默认 pair 的 min |
| 输出 dp[tot] 而非 dp[tot-1] 的疑惑 | n=3，tot=8=1000；全部猫是 7=111 | 最大合法集合编号为 `(1<<n)-1` |
| 不理解不可达判断或它是否更快 | 本题所有子集均可达，按 mask 升序时该判断不会跳过状态 | 可保留表达合法性，但不指望本题靠它加速 |
| DFS 循环中使用 c[i] | i 是车编号；例如当前猫重 6，某车剩 5，若误读另一猫重 1 会错误放入 | 始终用当前猫 c[cur] |
| 某辆车放不下就在 else 新开 | 车 1 剩 1、车 2 剩 8、当前猫重 5，车 1 不合适不代表必须开新车；反之能放旧车时仍可能需搜索开新分支 | 旧车循环后独立开新车一次 |
| 在 `i<=cnt` 的循环里 cnt++ | 同时改变枚举上界，且返回后本层 cnt 未恢复，可能不断扩张循环或越界 | 传 `cnt+1`，本层 cnt 不变 |
| `memset(sheng,w,sizeof sheng)` | memset 按字节填充；w=10 时常见 4-byte int 变成 0x0A0A0A0A，不是 10 | `fill(sheng,sheng+N,w)` |

当前版非错误但可改进：`cnt>ans` 改 `>=`；ans 从 n 起而非 21；全局 cnt 被形参遮蔽且未使用，可删除。最终版已包含成对恢复操作，不登记为“本次忘记回溯”。

## 可迁移经验

1. 状态设计从“暂停后继续需要哪些信息”出发；对照两个相同状态却后续选择不同的局面，检查信息是否遗漏。
2. 写 DFS 前先给参数、循环变量、数组下标标注角色，防止猫编号和车编号串用。
3. 一层固定当前对象；循环生成已有选择，额外选择单独写；共享状态先修改、递归、再恢复。
4. DP 三个对象分清：旧答案、加入选择后的候选答案、目标状态已有答案。
5. 手动检查“刚好装满”“第一步从空集合转移”“同车数剩余不同”“较少车但空间小”这些局面。
