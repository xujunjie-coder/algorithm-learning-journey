## 题意和约束

各排左对齐，从后往前人数不增；每排从左到右、每列从后到前身高严格递减，所有学生身高不同。最多五排，总人数最多 30；输出保证适合 32 位无符号整数。未给定确切内存限制，不推断某种数组一定超限。

## 本次真实推导路径

1. 从两排容量 `(2,1)` 开始。用户最初认为最高者可以放第一排任意位置；检查右上格的左邻居必须更高后，确认最高者只能在左上角。
2. 用户判断剩下两个格子都能放第二高者。由逐个安排从高到矮的学生，建立合法放置规则：存在的左邻格、上邻格必须已经有人。
3. 在 `(3,2,1)` 的小图上练习可放位置。用户能判断 `(2,0,0)` 只能增加第一排或第二排，第三排暂时不能增加。
4. 比较编号不同但占用格子相同的两种前缀。用户判断未来可选位置相同；每排占用连续前缀，因此可以只记录各排已放人数。
5. 用户尚不知道如何枚举全部排列。借 `(2,1)` 的两条选择路径解释搜索，以及试完一个选择后恢复以尝试其他选择；用户能解释撤销原因。
6. 两条路径到达相同人数状态 `(2,1,0)`。用户主动指出可以用“记忆化搜索”。
7. 定义 `dfs(a,b,c)` 为从当前状态继续的方案数。用户确认全满时返回 1，因为已经完成一种排列。
8. 用户逐步写出三个合法转移，并扩展到五排。值传递的参数表达式不修改当前层人数，因此此实现不需要手动恢复参数。
9. 区分“访问过就返回 0”与“返回已计算方案数”：不同前缀均可接上相同的一组后缀，必须各自累加，记忆化只省重复计算。
10. 讨论数组内存。用户最初认为第二排最多 29 人；用前两排至少 `2x` 人推出上限 15，用户随后推出第三排上限 10。第 i 排容量至多 `floor(30/i)`。
11. 用户询问内存计算，学习“各维长度之积 × 单元素字节数”；五维数组 `[31][16][11][8][7]` 共 305536 个 long long，2444288 字节，约 2.33 MiB。五个维度均为 31 时约 218.42 MiB。
12. 用户询问初始化为什么使用 `<=`。以容量 `(2,1,0,0,0)` 和非终点状态 `(2,0,0,0,0)` 解释：已放人数包含容量本身，零容量也要处理下标 0；用户明确表示理解。

## 已形成的状态与转移

`dfs(a,b,c,d,e)` 返回五排当前已放人数对应的后续合法排列数量。人数和决定下一名学生，无需额外记录编号。

- 终点：所有已放人数等于对应容量，返回 1。
- 第 0 排：`a < n[0]` 时可以增加 a。
- 其他排 i：已放人数小于容量，且前一排已放人数严格大于本排已放人数。
- 各合法分支的返回值相加，缓存这个总和。
- 缓存未计算标志为 -1，判断条件是 `!= -1`，不能仅判断是否非零。

正确性要点：每步放置当前剩余最高者，上方及左方均已放置保证新引入的行列约束成立；每个合法完整排列都有唯一的按身高递减放置顺序，搜索分支不重不漏。相同人数状态的剩余约束一致，故可复用后缀计数。

设各排容量为 n_i，状态数上界 S=乘积(n_i+1)，时间 O(kS)，记忆空间 O(S)，递归栈 O(N)。固定声明的数组无论实际访问多少状态均占其全部声明空间。

## 用户代码中的实际问题及最小反例

1. 初版三维 `fill(memo,memo+N,-1)` 不能如此填充整个三维数组；可按最内层行逐行 fill，或遍历全部维度。
2. 初版缓存判断 `if(memo[a][b][c])` 把 -1 当作已计算；应与 -1 显式比较。用户后续已改正。
3. 初版 `ans` 为 int，可能无法承载题目保证的无符号 32 位范围；用户后续改为 long long。
4. 当时五维实现的 init 五层循环仍为 `< n[i]`。下标语义是已放人数，范围为闭区间 `[0,n[i]]`；应全部改为 `<= n[i]`。零容量会使 `<` 的循环执行零次，因此初始缓存仍为全局默认值 0，搜索会误命中。首次输入 `1 / 1 / 0`（斜杠代表换行）即可揭示：正确答案 1，所贴版本输出 0。
5. 当时 main 每组没有清零 n。若前一组五排、后一组一排，则后四个容量残留。每次读取 k 后先 `fill(n,n+5,0LL)`，再读前 k 个容量。可用两组 `5 / 1 1 1 1 1 / 1 / 2 / 0` 检查切换；必须先修正初始化再独立验证本问题。

缓存命中时 `ans += memo[...]` 然后保存返回，在 ans 初始为 0 且放在 else 结构下时是正确的；直接 return 缓存只是简化，不标成错误。
