# 枚举第一行与逐行递推

## 解决的问题

处理固定宽度网格中的局部翻转问题：一次操作只影响当前位置及其上下左右相邻位置，目标是在限定操作次数内使整个网格达到指定状态。

## 识别信号

- 网格宽度很小，例如本题宽度固定为 `5`；
- 每个位置的操作只有“按/不按”两种选择；
- 操作具有局部影响，尤其会影响上下相邻行；
- 一旦前一行的操作状态确定，下一行的操作就会被强制决定；
- 需要求最少操作次数，或者判断是否存在满足限制的方案。

## 前提与限制

- 网格宽度为 `m` 时，第一行最多枚举 `2^m` 种方案；
- 逐行递推成立的关键是：处理第 `i` 行时，只有第 `i+1` 行的操作还可能影响第 `i` 行；
- 本题目标是所有灯变亮，即所有状态变为 `1`；如果目标改为全 `0`，递推条件和最终检查需要相应反转。

## 核心思路与不变量

第一行没有上一行可以约束，因此必须枚举第一行的完整按法。固定第一行后，从第二行开始逐行处理：如果上一行对应位置仍为 `0`，就必须按当前行对应位置，使上一行该位置变成 `1`。

处理到第 `i` 行后，第 `i-1` 行已经被确定为目标状态，后续操作不会再改变它。最后检查第五行是否全部为 `1`，即可判断当前第一行方案是否合法。

`mask` 的第 `j` 位表示第一行第 `j` 列是否按：

```cpp
if ((mask >> j) & 1) {
    press(board, 0, j);
}
```

## 标准模板

见 [5×5 拉灯枚举第一行模板](../../templates/lights-out-first-row.cpp)。

模板中的 `press` 函数使用 `^= 1` 翻转状态，并通过边界判断避免访问网格外的位置。

## 常见变体

- 目标状态为全 `0`：上一行是 `1` 时按当前行，最后检查上一行是否全 `0`；
- 网格宽度不是 `5`：将 `1 << 5` 改为 `1 << width`，并相应调整数组；
- 只要求判断是否存在方案：找到一个合法方案后可以提前结束；
- 用每一行的 5 位整数代替二维数组，进一步进行状态压缩优化。

## 易错点

- 必须先完成第一行的一个完整 `mask`，再开始后续行递推；
- 状态变化是翻转，不能把 `b[x][y] ^= 1` 写成 `b[x][y] = 1`；
- 翻转上下左右时必须检查下标边界；
- 目标为全 `1` 时，上一行是 `0` 才按当前行；
- 最后一行出现 `0` 才表示当前方案失败；
- 第一行方案应枚举 `0 <= mask < (1 << 5)`，不能从 `1` 开始或使用 `<=`；
- 非法方案返回 `INF`，合法方案返回实际操作次数 `step`；
- 每组棋盘都必须重新初始化答案，并且要对所有 `mask` 取最小值；
- `mask >> j & 1` 等价于 `(mask >> j) & 1`，只检查移动后的最低位。
- 输入是字符 `'0'`、`'1'` 时，应使用 `c - '0'` 转成整数 `0`、`1`，不能误写成 `c - 'a'`。

## 复杂度

本题每组数据枚举 `2^5 = 32` 种第一行方案，每种方案处理 `25` 个位置，时间复杂度为 `O(2^5 × 5^2)`，额外空间复杂度为 `O(5^2)`。

## 我的经验

本题开始时我知道要枚举第一行，但还没有把代码拆成“完整处理第一行”和“后续逐行递推”两个阶段。后来明确了：第一行是自由选择，后面各行由上一行的最终状态强制决定。

本题还暴露出多个实现层面的错误：把翻转写成赋值、忘记边界判断、把目标状态判断写反、mask 范围错误、返回值错误、答案没有重置或没有输出。以后写这类题时，应先分别检查“状态如何变化”“合法条件是什么”“枚举范围是什么”“返回值代表什么”。

重写代码时还出现过把 `a[i][j] = c - '0'` 误写成 `a[i][j] = c - 'a'`。字符 `'0'` 和 `'1'` 的数值转换必须减去字符 `'0'`；`'a'` 适用于字母编码，不适用于数字字符。
