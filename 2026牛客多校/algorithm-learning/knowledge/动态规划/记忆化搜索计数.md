# 记忆化搜索计数

## 解决的问题

搜索中不同选择路径到达同一个状态，且未来合法选择和后续方案数只取决于该状态。缓存每个状态的后续方案数，避免重复展开。

## 识别信号

可以先写出暴力搜索；存在大量重复子问题；状态能保留所有影响未来的信息，状态数量可控。本题按身高递减放人，每排占用连续前缀，只需记录各排已放人数。

## 前提与限制

合并的状态必须具有相同的未来行为。本题每次人数和增加 1，因此无环；直接缓存不适用于包含未处理循环依赖的递归。各计数分支必须对应互不重叠的选择。

## 核心思路与不变量

dfs(state) 返回从当前状态继续到合法完成的方案数。合法完成返回 1；无合法后续返回 0；未计算标记用 -1。答案是每个合法下一状态返回值的和，计算后存入缓存。

不同前缀到达同一状态时，每个前缀都要累加该状态的后缀数。例如两个前缀各能接 x 种后缀，共贡献 2x；不能用 visited 去重后直接返回 0。

## 标准模板

先明确状态、合法下一步与终点，再加入查缓存和存缓存，不从背模板替代推导。已验证来源为用户报告 AC 的[班级合照原版](../../reviews/young-tableaux-photo-submitted.cpp)。本题专用的[五排前缀计数模板](../../templates/row-prefix-memo-count.cpp)只适用于其注明的容量限制，不是任意五维问题的通用数组。

## 常见变体

### 同题的递推 DP

DFS 定义是“从当前状态出发的后缀方案数”；本次递推 DP 改为“从空队形到达当前状态的前缀方案数”。这是两种不同的状态值含义，不能只替换变量名而忽略初始化和转移方向。

```cpp
memset(dp, 0, sizeof dp);
dp[0][0][0][0][0] = 1;
// 五层循环均从 0 递增到对应 n[i]，包含端点。
if(b < n[1] && a >= b+1)
    dp[a][b+1][c][d][e] += dp[a][b][c][d][e];
```

空队形人数是 0，但有一种空安排，故起点值为 1。用户初次回答 0，说明人数和方案数混淆；讲解后能正确回答两种前缀贡献 2，独立给出第二排的累加形式。用户能说明循环递增是因为必须先有前驱再有后继，能指出最终取五排全满的状态。

嵌套循环的正确性：每次只增加一个坐标，其余坐标不变，所以目标在字典序中严格靠后；处理目标前全部前驱已处理。无效人数状态初始为 0，合法转移不会给它们增加计数；可不显式跳过。答案为 dp[n[0]][n[1]][n[2]][n[3]][n[4]]。

S=乘积(n[i]+1)，递推时间 O(5S)，固定数组约 2.33 MiB，无递归栈。当前 dp 中非零状态形成相应子杨图，其计数亦在本题规模下可由 long long 承载。

[DP 参考代码](../../reviews/young-tableaux-dp-reference.cpp)由助手按用户原写法提供；[正式模板](../../templates/row-prefix-dp-count.cpp)及[本地验证记录](../../reviews/young-tableaux-methods-verification.json)。用户未补交 DP 或报告此版在线 AC；同题补充方法不重复增加 encounter。

布尔可行性、最小值与计数的返回含义不同；缓存语义和聚合运算必须分别定义。计数缓存不是普通访问标记。

## 易错点

- -1 也是非零，不能用 if(memo) 判断是否计算过。
- 状态下标表示已放人数时范围为 [0,容量]，初始化必须包含等于容量的状态；容量为 0 也要初始化下标 0。
- 多组数据要重置容量和本组缓存；不存在的排设为 0。
- 终点返回 1 表示完成一种方案，不是“已经没有人可放就返回 0”。
- 按值传入 a+1 不修改当前层参数；共享数组原地修改才需要恢复。
- 数组内存按声明元素个数计算，而非按实际访问状态计算。
- 题目保证无符号 32 位范围，不意味着有符号 int 能装下；本题使用 long long。

## 复杂度

每状态最多 B 个转移、有效状态数 S 时，时间 O(BS)，缓存空间 O(S)，另计递归深度。五排问题 S 上界为各排 (n_i+1) 的乘积，B 至多 5。固定模板数组 305536 个 long long，约 2.33 MiB，递归深度至多 30。
