# 递归式推导

## 解决的问题

把一个规模为 (n) 的问题拆成若干个规模更小、结构相同的子问题，并用递推式描述总成本、方案数或最优值。

## 识别信号

- 题目对象有明显的规模参数 (n)；
- 存在一个必须先完成或最后完成的关键动作；
- 关键动作前后会出现同类的更小问题；
- 问题允许通过改变起点、终点或参数继续使用同一求解过程。

## 核心思路与不变量

先定义状态 (T(n)) 的准确含义，再围绕关键动作拆分：

\[
T(n)=\text{前置子问题代价}+\text{关键动作代价}+\text{后置子问题代价}.
\]

对于最优问题，递推式的正确性通常需要两部分：

- 必要性：任何合法方案都必须完成这些阶段，因此得到下界；
- 可行性：按照递归方案执行可以达到这个下界。

## 标准模板

```text
定义 T(n)：规模为 n 的问题的目标值。

选择一个必须发生的关键事件。

关键事件前：拆成若干个规模更小的同类子问题。
关键事件本身：增加固定代价 c。
关键事件后：再拆成若干个规模更小的同类子问题。

合并得到递推式：
T(n) = 前置部分 + c + 后置部分。

补充最小规模的边界条件。
最后检查递推式是否同时满足必要性和可行性。
```

## 常见变体

- 计数型递推：统计方案数量；
- 最优化递推：先证明下界，再证明构造能达到；
- 多参数递归：把起点、终点、状态等作为函数参数；
- 递归输出：递推式描述步骤数，递归函数实际输出每一步操作。

## 汉诺塔实例

令 (H(n)) 表示把 (n) 个盘子从任意起点柱移动到任意终点柱的最少步数。

最大的盘子移动前后分别需要解决一个 (n-1) 盘子问题，最大盘子本身移动一次：

\[
H(n)=H(n-1)+1+H(n-1)=2H(n-1)+1,
\qquad H(1)=1.
\]

若要求输出移动过程，递归函数的三个部分依次是：

1. `hanoi(n - 1, from, to, auxiliary)`；
2. 移动最大盘子；
3. `hanoi(n - 1, auxiliary, from, to)`。

## 易错点

- 只描述了一种方案，却没有证明它是最优方案；
- 忘记边界条件；
- 没有准确说明递归参数的含义；
- 推导 T(n) 时过早把 T(n-1) 展开成 T(n-2)、T(n-3)，导致看不清当前层的结构；
- 把两个结构相同、柱子角色不同的子问题误认为不同算法；
- 将递推式和递归代码混为一谈：递推式说明规模关系，代码还需要明确参数、终止条件和执行顺序。

## 复杂度

复杂度必须根据递推式和输出要求分别分析。汉诺塔有：

\[
H(n)=2^n-1.
\]

只计算数量时递归深度为 (O(n))；输出全部操作时，时间至少为输出规模 (O(2^n))，递归栈为 (O(n))。

## 我的经验

本题通过教练式提问逐步得到：先把 (n-1) 个盘子移到辅助柱，再移动最大盘子，最后把 (n-1) 个盘子移到目标柱。三段代价分别为 (H(n-1),1,H(n-1))，边界为 (H(1)=1)。

需要继续练习的是：看到新递归题时，先自己寻找“必须发生的关键事件”，不要直接套用 (2T(n-1)+1)。
